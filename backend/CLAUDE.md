# Backend — FastAPI modular monolith

Python 3.13, FastAPI, SQLAlchemy 2.0 (async) + asyncpg, Alembic, Pydantic v2, pydantic-settings,
PostgreSQL 17 + pgvector, Redis + Taskiq, Anthropic Python SDK. Package manager: **uv**. (docs/STACK.md)
Runnable reference code: `modular-monolith` skill (core, shared, `visa` module, conftest) and
`payments-billing` skill (`catalog`, `billing` with providers). Also `llm-rag`, `i18n` skills.

## Structure

```
backend/
├── app/
│   ├── main.py              # composition root: create_app() wires routers, error handlers, providers, events
│   ├── core/                # config, db/session, event bus, outbox, security, logging — no business logic
│   ├── shared/              # errors, i18n (Locale, LocalizedText), money (Money), pagination — no business logic
│   └── modules/
│       │   # platform
│       ├── auth/            # registration, login, JWT, Telegram login
│       ├── users/           # profiles, target visa/job, JLPT level, preferences, locale
│       ├── files/           # uploads + generated documents in object storage (S3-compatible), signed URLs
│       ├── notifications/   # email, Telegram messages (Bot API, direct), in-app, deadline reminders
│       ├── ai/              # Anthropic gateway: client, prompts, streaming, usage/cost tracking
│       ├── rag/             # document ingestion, chunking, embeddings, retrieval (pgvector)
│       │   # paid services (core business)
│       ├── catalog/         # products, prices PER CURRENCY, what each product grants
│       ├── billing/         # checkout, national + international payment providers, webhooks, ENTITLEMENTS
│       ├── orders/          # human-fulfilled purchases, status workflow, deliverables
│       ├── experts/         # consultants/reviewers: profiles, availability, bookings, payouts data
│       ├── resume/          # 履歴書 + 職務経歴書 builder, AI help, PDF export
│       ├── interview/       # AI mock interviews, question banks by job & visa, feedback reports
│       ├── visa/            # visa types, eligibility checker, checklists, status & expiry tracking
│       ├── guides/          # life-in-Japan guides (city hall, insurance, bank, housing), sourced & dated
│       │   # learning (one section of the product)
│       ├── learning/        # courses, lessons, vocabulary, kanji, SRS reviews
│       ├── assessment/      # JLPT mock tests, placement tests, scoring
│       └── tutor/           # AI language tutor chat (uses ai + rag facades)
├── migrations/              # Alembic (one shared history)
├── tests/                   # cross-module / end-to-end tests
├── conftest.py              # shared fixtures for ALL tests (must be here, not in tests/)
├── .importlinter            # GENERATED by scripts/sync_importlinter.py (`make importlinter`)
└── pyproject.toml           # ruff: line-length 120, isort known-first-party = ["app"]; pytest asyncio_mode = auto
```

### Inside every module — packages, never 1000-line files

```
modules/<name>/
├── __init__.py              # one-line docstring: what this bounded context owns
├── public.py                # THE ONLY thing other modules import: facade class(es) + DTOs (+ re-exported events)
├── testing.py               # (optional) factories other modules' TESTS may use to create this module's data
├── routers/                 # HTTP layer — thin: parse → service → schema
│   ├── __init__.py          #   router = APIRouter(prefix="/api/v1/<name>"); include_router(...) per resource
│   ├── deps.py              #   Depends() wiring: session → services; today(); module-specific guards
│   └── <resource>.py        #   one file per resource: status.py, checkout.py, webhooks.py …
├── services/                # use cases (application layer); no HTTP, no commit
│   ├── __init__.py          #   re-exports the service classes
│   └── <use_case>_service.py
├── providers/               # (optional) adapters to external systems, one package per provider
├── schemas/                 # Pydantic API contract (request/response), one file per resource
├── repositories/            # all SQL for this module, one repository per aggregate
├── models/                  # SQLAlchemy models, one file per aggregate; __init__ imports all (Alembic)
├── domain/                  # pure rules: enums.py, rules.py / state_machine.py, events.py, exceptions.py
├── handlers/                # (optional) reactions to other modules' events
├── jobs/                    # (optional) Taskiq background tasks
└── tests/                   # unit (domain, services) + API tests for this module; conftest.py for module fixtures
```

**Layers (enforced by import-linter, `module-layers` contract):** a layer imports only layers below it.

```
testing
routers | public | handlers | jobs      ← siblings: may not import each other
services
providers
schemas | repositories
models
domain
```

**File size (enforced by the `size_guard` hook):** Python ≤ 400 lines (tests ≤ 600). Split by responsibility —
a new resource gets its own `routers/<resource>.py`, `schemas/<resource>.py`, a new use-case group its own
`services/<name>_service.py`, a new aggregate its own model + repository file. Never "utils.py" dumping grounds.

## Rules

- **Boundaries:** other modules import only `app.modules.<x>.public` (tests may also use `<x>.testing`).
  Facades return DTOs/dataclasses, never ORM objects. No cross-module foreign keys — store the id and resolve
  via the facade. Foreign keys *inside* a module are fine.
- One request = one transaction, **committed before the response is sent**: inject the session only as
  `SessionDep` (`Depends(get_session, scope="function")`). Services and repositories never commit. Routers never
  open or use the session — services come from `routers/deps.py` (import-linter forbids `sqlalchemy` in routers).
- `ENV` is required (`local|test|staging|production`); fake/skeleton payment adapters run only in local/test.
- Events: `bus.publish(session, event)` runs handlers after commit; `durable=True` writes to `core_outbox` in the
  same transaction (anything that must not be lost: reminders, receipts, orders after payment).
- Everything async. No blocking I/O in request path; heavy jobs (PDF, ingestion, embeddings) go to Taskiq.
- Errors: module exceptions in `domain/exceptions.py` subclassing `AppError` with a code `<module>.<reason>`.
- Config only through `app.core.config.settings`. Never read `os.environ` elsewhere.
- Migrations: `uv run alembic revision --autogenerate -m "<module>: <change>"`, then **read and fix** it.
  Never edit a migration already merged into main (a hook blocks it).
- API: all routes under `/api/v1`, explicit `response_model=`, pagination by cursor for lists.

## Languages (uz · ru · en · ja)

- `users.locale` is the user's language (default `uz`); requests without a user use `Accept-Language`,
  resolved by `app.shared.i18n.locale_from_request` to one of the four.
- **API errors return codes, not sentences:** `{"error": {"code": "resume.photo_too_large", "params": {...}}}`.
- Translatable content (catalog products, guides, visa pages, lesson meanings) uses `LocalizedText`
  (JSONB `{"uz","ru","en","ja"}`, `uz` required); responses return the resolved string + its `lang`.
- Emails/Telegram notifications are rendered per recipient locale from `notifications/templates/<locale>/`.
- AI answers in the user's locale; resume output is always Japanese, explanations in the user's locale.

## Paid services — national + international payments

Details and runnable code: `payments-billing` skill.

- **Money** is `app.shared.money.Money(amount_minor: int, currency: str)` — integer minor units + ISO 4217.
  Never floats. Prices live only in `catalog`, **one row per currency** (UZS for national checkout; USD/JPY/EUR
  for international) — no FX conversion. The client sends `product_id` + `currency`; the server computes the amount.
- **Providers** implement one `PaymentProvider` contract, one package each under `billing/providers/`:
  national (UZS): Rahmat (ADR 0002 — one integration covers cards and Click/Payme/Uzum wallets);
  international: Rahmat if it accepts foreign-issued cards, otherwise Octo (ADR 0003). Only providers listed in
  `PAYMENT_PROVIDERS_ENABLED` are active. UZS checkout offers national providers first, other currencies
  international ones.
- **Webhooks** `/api/v1/billing/webhooks/{provider}`: the adapter verifies signature/credentials FIRST, validates
  the payload and speaks the provider's protocol; the shared `WebhookLedger` locks the payment row and does
  idempotency (same txn → same answer, different txn on a paid payment → `billing.already_paid`), amount check,
  state machine, grants from the checkout snapshot and the durable `PaymentSucceeded` event — one transaction,
  committed before the provider gets its ack.
- Startup refuses: unknown providers, enabled providers without credentials, `fake` outside local/test, and
  adapters marked `ready=False` (Rahmat until verified on its sandbox) outside local/test.
- **Entitlements are the only access check:** `Depends(require_entitlement(Key.X))` or `BillingFacade.has_access`.
  Quota is consumed **after** the paid action succeeded.
- **Orders** (human-fulfilled) are created from `PaymentSucceeded` when `fulfilment == "human"`; status flow
  `created → paid → in_progress → delivered → completed` (+ `cancelled`/`refunded`), SLA, deliverables via `files`.
- Free tier shows real value first; price, what's included and refund terms visible before paying.

## Resume (module `resume`)

- Structured data model (education, work history, licences/qualifications, JLPT, 志望動機, 自己PR), versioned.
  Both Japanese formats render from the same data: JIS-style 履歴書 and 職務経歴書, plus an English CV.
- AI translates/rewrites into business Japanese (keigo) via `ai.public`; the user approves before export.
- PDF rendering runs in the worker: headless Chromium via Playwright (ADR 0005), trusted HTML template → A4 PDF,
  JavaScript and network disabled during render, Japanese fonts embedded, stored via `files`.

## Interview (module `interview`)

- Question banks by job field and visa. AI interviewer role-plays a Japanese employer, then produces a scored
  report (language, content, etiquette) with improved sample answers.
- Voice mode waits for an ADR (speech-to-text provider undecided); store transcripts, not raw audio by default.

## Visa (module `visa`)

- **Information, not legal advice** — every page cites its official source and date and offers a paid
  consultation with a licensed specialist (行政書士) via `orders`/`experts`.
- Saved residence status + expiry → reminders at 90/60/30 days (durable event → notifications).

## AI / Anthropic (module `ai`) and RAG (module `rag`)

See the `llm-rag` skill. Only `modules/ai` imports `anthropic`; model ids from settings; usage recorded per
user + feature; prompts versioned in `modules/ai/prompts/`. RAG: pgvector + full-text, reciprocal-rank fusion,
chunks keep `lang`, `source_title`, `source_url`, `published_at`, `embed_model`; visa/guide answers cite sources.

## Commands (from backend/)

```
uv run fastapi dev app/main.py         # app/main.py exposes `app = create_app()`
uv run pytest -q                       # or: uv run pytest app/modules/<name>
uv run ruff check --fix . && uv run ruff format .
uv run mypy app
uv run lint-imports                    # boundaries + layers (run `make importlinter` after adding a module)
uv run alembic upgrade head
```

Testing: pytest + pytest-asyncio + httpx `AsyncClient`, **PostgreSQL** test DB (`TEST_DATABASE_URL`) — each test
runs in a rolled-back outer transaction (SQLite can't do this). Shared fixtures in `backend/conftest.py`,
module fixtures in `app/modules/<name>/tests/conftest.py`, cross-module test data via `<module>.testing`.
